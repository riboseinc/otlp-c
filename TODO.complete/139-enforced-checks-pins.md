# TODO 139 — Enforced Release checks + complete upstream pinning + spec reference

**Status:** Complete (v0.5.99)
**Priority:** P1 (v0.5.98's core claim was overstated)

## The gap

**1. v0.5.98's helpers didn't actually enforce anything in
Release.** `check_true(cond)` was `assert(cond); (void)cond;` —
under NDEBUG, assert is elided and `(void)cond` discards the
result: the expression EXECUTED (the point of the sweep), but a
FALSE check did not fail the test. The v0.5.98 changelog claimed
"the suite now verifies identically in Debug and Release" —
wrong: Release runs executed the checks without enforcing them.
All plain-Release CI jobs passing was consistent with
non-enforcing checks.

**2. The upstream-literal pins covered 6 of 31 tables.** v0.5.97
pinned the metrics data-point tables + Metric + LogRecord flags.
The other 25 (traces envelope, Span/Event/Link/Status, AnyValue
family, metrics envelope/Sum/Gauge/Hist/EH, logs envelope) had
no independent reference — drift there would be invisible until
a collector choked.

**3. docs/otlp-spec.md documented traces only.** The metrics and
logs message schemas were entirely absent from the protocol
reference — the gap that let the HDP min/max bug (v0.5.97) hide
for the schema's whole life.

## What shipped

**Enforced helpers** (`tests/test_util.h`): `check_true` /
`check_ok` now abort on failure in EVERY configuration, printing
the call site (`__FILE__`/`__LINE__` pinned via single-expression
macros; the logic lives in `check_true_at`/`check_ok_at` inline
functions — no control flow in macros, per project style).
Mutation-tested: a deliberately drifted schema field aborts with
a diagnostic in both Debug and Release builds.

**Complete pinning** (`tests/unit/test_unit_wire_numbers.c`):
the hand-rolled pins test is replaced by a table-driven sweep —
one `wire_pin` array per message, all 31 tables in
`src/otlp_schema.h` pinned (field number + wire type) against
literals copied from the opentelemetry-proto .proto files. A
failed pin names the table and both values. The two wire-walk
tests (HDP, EHDP end-to-end) are unchanged.

**Full cross-check result**: all 31 tables match upstream —
including the AnyValue oneof (string=1/bool=2/int=3/double=4/
array=5/kvlist=6/bytes=7, re-verified against the live
common.proto; an earlier recollection of array=6/kvlist=7/
bytes=8 was stale — the re-fetch is exactly why literals are
always verified live, never from memory).

**Spec reference completion** (`docs/otlp-spec.md`): new
"Metrics messages" and "Logs messages" sections — every message
with proto block and field numbers, reserved fields called out
(NDP/HDP field 1, Metric 4/6/8, LogRecord 4), the not-emitted
fields marked, the varint-vs-fixed32 flags asymmetry noted, the
packed-varint vs packed-fixed64 bucket-counts asymmetry noted,
and the v0.5.97 min/max story recorded at the site it happened.
Points contributors at `src/otlp_schema.h` (canonical) and
`unit-wire-numbers` (executable enforcement).
